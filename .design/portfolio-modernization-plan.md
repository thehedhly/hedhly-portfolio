## 1. Agreed direction

Build a terminal-styled ("geeked-up") portfolio modelled on the interaction and composition of [Allie the Icon](https://allietheicon.com/) and its [terminal menu](https://allietheicon.com/forhire/). Use Hamza's existing DevSecOps content and the exact [Ayu Dark](https://terminalcolors.com/themes/ayu/dark/) / [Ayu Light](https://terminalcolors.com/themes/ayu/light/) palettes.

| Requirement | Decision |
| --- | --- |
| Primary action | **→ EXPLORE** in both languages, replacing the reference's "→ AVAILABLE FOR HIRE". |
| Future job search | One flag in `src/config/site.mjs` switches CTA and status copy to "for hire". An owner-facing comment sits beside the flag **and** where the CTA is rendered (§9). URLs never change. |
| Default language | German. `/` → 301 → `/de/`. English is complete under `/en/`. No IP- or `Accept-Language`-based redirects. |
| Default theme | Ayu Dark, with Ayu Light selectable. An explicit choice persists in `localStorage`. |
| Top bar | Prompt on the left. On the right: theme selector, DE/EN links, and Exit. All of them remain usable at 320 px. |
| Contact | the owner's contact address appears only after an explicit click/Enter. The initial HTML/DOM has no plaintext address or `mailto:` (§8). |
| Content | Keep expertise, career history, the three project outcomes, certifications, LinkedIn, GitHub, and Düsseldorf. Invent nothing. |
| Delivery | Static HTML generated by a dependency-free Node build into `dist/`. Vanilla CSS/JS. Deployed through the existing Cloudflare Pages project. |
| Discovery | Every section is a real, directly loadable, server-rendered URL. Motion only enhances content that is already rendered. |

Success criterion: within a few actions, a visitor (human, crawler, or agent) can tell who Hamza is, check the relevant evidence, and make contact.

### 3.3 Behaviour (measured)

- **The content swap is instant.** A MutationObserver showed the old output removed and the new one inserted within 4 ms of the click. There is no typing effect and no transition. The terminal feel comes entirely from layout, colour, the prompt/command framing, and the cursor.
- **The URL hash tracks the selection** (`#engineering`, `#product`, `#show`, `#all`) without growing history. Loading `/forhire/#show` directly opens that section.
- **Clicking the selected item collapses it** and clears the hash.
- **Number keys 1–4 work anywhere on the page.** No scroll happens on selection.
- Built as a Next.js static export with React state.

### 3.4 Where the reference is weak, and what we do instead

| Reference | Problem | Hamza's site |
| --- | --- | --- |
| Section content exists only after a click (`curl` of `/forhire/` has no "I build the whole thing") | Crawlers and simple agents never see the services | Each section is its own server-rendered URL |
| No meta description, canonical, `lang` alternates, JSON-LD, or sitemap (`/sitemap.xml` → 404) | Weak snippets and no identity signals | Full metadata, ProfilePage/Person, sitemap with hreflang |
| `robots.txt` contains only Cloudflare's managed "Content Signals" comment preamble, with no directives | Shows that Cloudflare can inject or override robots.txt | Owner-controlled robots.txt; check the dashboard toggles (§11.3) |
| Email is a plain `mailto:` in the DOM | Easy to scrape | Click-to-reveal (§8) |
| EXIT label generated in CSS; menu items are buttons with no URLs | Poor accessibility; no shareable, indexable section links | Real text links with `aria-current="page"` |
| Cursor blinks forever | WCAG 2.2.2 (blinking longer than 5 s without a pause control) | Cursor stops blinking after 4 cycles (§5) |
| Number keys are global with no way to turn them off | WCAG 2.1.4 (single-character shortcuts) | Toggle provided; ignored inside form controls and with modifier keys (§6) |

### 4.4 Theme, language controls, and typography

- Native `<select>` with the options **Ayu Dark** / **Ayu Light** and a localised label.
- Render `data-theme="ayu-dark"` on the server. A tiny external bootstrap script (external because the CSP allows no inline scripts) applies an allowlisted `localStorage` value before first paint, sets `color-scheme` and `theme-color`, and catches storage errors.
- Dark is the default on first visit even when the OS prefers light. Re-sync on `pageshow` (bfcache).
- No theme URLs. Changing the theme never changes the route, scroll position, or focus.
- DE/EN are native links to the **equivalent document**. Exit goes to the current language's homepage; on the homepage that slot is empty.
- Font stack: `ui-monospace, "SF Mono", SFMono-Regular, Menlo, Monaco, "Cascadia Code", Consolas, "Liberation Mono", monospace`. Body 16 px / 1.65. No web fonts.
- Responsive:
  - The prompt and control row stack below about 560 px.
  - German labels wrap; only the decorative path text shortens.
  - Touch targets ≥ 44 px, `scroll-padding-top` under the fixed bar, safe-area insets, and no horizontal page scroll.
  - Verify at 320, 390, 768, and 1440 px and at 200 % zoom.

## 5. Animation specification

Principles from the reference: a cursor, colour transitions, inverted selection, and **instant** content. We add one geeky detail, a short "typed" command line, and it never delays the content.

```css
/* motion.css: all motion lives here and is switched off by one media query */
@keyframes blink   { 0%, 50% { opacity: 1 } 50.01%, 100% { opacity: 0 } }
@keyframes type    { from { width: 0 } }
@keyframes out-in  { from { opacity: 0; transform: translateY(4px) } }

/* Cursor: 4 cycles (< 5 s, WCAG 2.2.2), then stays visible */
.cursor            { background: var(--cursor); color: var(--canvas); padding: 0 2px;
                     animation: blink 1s steps(1, end) 4; }

/* Menu: colour response and inverted number on hover or selection */
.menu a            { transition: color 150ms ease; }
.menu a:hover,
.menu a[aria-current="page"]            { color: var(--accent-text); }
.menu a[aria-current="page"] .num       { background: var(--accent); color: var(--canvas); padding: 0 2px; }

/* Typed command: pure CSS, the text is always in the DOM. --len is set at build time */
.cmd-typed         { display: inline-block; overflow: hidden; white-space: nowrap; vertical-align: bottom;
                     width: calc(var(--len) * 1ch);
                     animation: type calc(var(--len) * 18ms) steps(var(--len)) both; }

/* Output: appears immediately, with a 160 ms fade */
.output            { animation: out-in 160ms ease-out both; }

/* Hover glow on the email chip and links, as in the reference, without a perpetual glow */
.chip:hover, .chip:focus-visible { box-shadow: 0 0 12px color-mix(in srgb, var(--accent) 40%, transparent); }

@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { animation: none !important; transition: none !important; }
}
```

| Element | Standard | Reduced motion |
| --- | --- | --- |
| Cursor (top bar and trailing prompt) | 1 s blink × 4, then steady | Steady |
| Typed command (`cat platform.md`) | 18 ms per character; a 15-character command takes 270 ms. Output fades in **at the same time** | Static text |
| Menu hover / selection | 150 ms colour; number inverted | Immediate |
| Output | 160 ms opacity + 4 px translate | Immediate |
| Contact reveal | Swap button → address with `out-in` | Immediate |
| Cross-document View Transition (optional) | ≤ 180 ms crossfade of `.output` only; `@view-transition { navigation: auto }` | Off |

Rules:
- Animate only `opacity` and `transform` (plus `width` on the short command span).
- No content is hidden waiting for JavaScript or an IntersectionObserver, unlike the current live hero.
- Decorative cursors and `#` prefixes are `aria-hidden`.
- A single polite live region carries only useful messages ("Geöffnet: Plattform", "Adresse kopiert"), never one per character.
- No perpetual ambient glow animation. A static gradient border is fine.

## 6. Navigation and interaction

### 6.1 Baseline: works with no JavaScript

The menu is made of plain `<a href>` links to real static routes. Each route's HTML already contains the selected output, so new tabs, refresh, Back, sharing, and crawling work natively.

| Interaction | Behaviour |
| --- | --- |
| Explore | Opens `/{lang}/explore/`. No boot delay. |
| Select item | Opens `/{lang}/explore/<doc>/` with `aria-current="page"` on the item, the typed command, and the output. |
| Click the selected item again | Links back to `/{lang}/explore/`. This is the URL equivalent of the reference's collapse. |
| Keys `1`–`4` | Open documents 1–4. `0` or `Esc` returns to the menu. Active on explore pages; ignored when focus is in a form control or a modifier key is held. A visible toggle ("Tastenkürzel: an/aus"), stored in `localStorage`, satisfies WCAG 2.1.4. |
| Direct load | Same selected state as arriving through the menu. |
| Back/forward | Native, or handled by `popstate` when the enhancement below is active. |

### 6.2 Enhancement: in-place swap (already in `menu.js`)

This is allowed because it reproduces the reference's instant swap. It must:
- Intercept only same-origin, unmodified, primary-button clicks on menu links.
- Fetch the real static page, take its `.output` and menu state, and update `document.title`, `aria-current`, the DE/EN link targets, and the canonical/alternate tags. Crawlers never depend on this.
- Use `pushState`, restore on `popstate`, and abort any request still in flight.
- Fall back to full navigation on any error or non-200 response.
- Focus stays on the activated menu link (deviation from the earlier draft): number keys only work while focus is inside the menu, so moving focus into the output would stop repeated presses. The polite status line announces the change instead.
- Never scroll the page unless the output's heading is out of view.

Not allowed: `role="menu"`, `role="application"`, or swapping content without a real URL.

## 8. Contact reveal

1. The initial HTML shows `E-Mail: [Adresse anzeigen]` / `Email: [Reveal address]` as a `<button>`. There is no address and no `mailto:` in the HTML, DOM, JSON-LD, meta tags, `index.txt`, `llms.txt`, `security.txt`, or sharing images.
2. On activation, `import()` the address module (base64 chunks, never preloaded or prefetched, no source maps). Replace the button with the readable address, a **Kopieren / Copy** button, and an **E-Mail schreiben / Write email** `mailto:` link.
3. A polite status announces the reveal or copy. Focus moves to the address. If the clipboard fails, the text stays selectable with a hint.
4. If the import fails, show Retry plus LinkedIn. With JavaScript off, a `<noscript>` points to LinkedIn.
5. Make sure Cloudflare **Scrape Shield → Email Address Obfuscation** cannot inject `/cdn-cgi/l/email-protection` scripts. They would be blocked by the CSP. With no address in the HTML it shouldn't trigger, but record the setting.

This deters harvesters. It cannot stop a headless browser that clicks. The next step up, if ever needed, is a contact relay with server-side abuse controls (for example a Pages Function with Turnstile). That is out of scope.

## 10. Static build and Cloudflare Pages delivery

### 10.1 Structure (matches the existing scaffold; adjust, don't rewrite)

```text
src/config/site.mjs          owner settings (availability, origin, defaults)
src/routes.mjs               route IDs, locale pairs, sitemap inventory
src/content/{shared.mjs,de.json,en.json}
src/templates.mjs            layout, home, explore/doc, 404 (split later if it grows)

public/                      _redirects, _headers, robots.txt, .well-known/security.txt, og images
dist/                        the only publish directory (git-ignored)
```

The build:
- Validates locale parity and escapes all output.
- Emits the 12 pages, `404.html`, `sitemap.xml` (with hreflang), `index.txt`, `en/index.txt`, and `llms.txt`.
- Fingerprints CSS/JS and copies only referenced images, so the old template images (`blog-*`, `project-*`, `avatar-*`, `logo-N-color`) are dropped.
- Fails on broken internal links, missing assets, or any match of the email address in `dist/`.

### 10.4 `public/_headers` additions

```text
/*
  X-Content-Type-Options: nosniff
  Referrer-Policy: strict-origin-when-cross-origin

  Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; object-src 'none'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'
```

## 11. Search, AI search, and agent visibility

### 11.1 Indexable pages

Every canonical route returns 200 with its language, substantive text, real links, and metadata before any JavaScript runs:
- Distinct titles, e.g. `Azure, Kubernetes & Cloud-Security | Hamza Hedhly`.
- Localised descriptions, absolute canonical and `og:*` URLs, image dimensions and alt text, a favicon, `apple-touch-icon`, and `theme-color`.
- Consistent trailing slashes.

### 11.2 Structured identity

- Keep the Person `@id` `https://hedhly.com/#hamza-hedhly` on every page.
- `ProfilePage` on home and profile; `WebPage` (with `about` → Person) on topic documents; one `WebSite` node with `inLanguage: ["de","en"]`.
- `sameAs` LinkedIn/GitHub, `knowsAbout`, and `hasCredential` (only credentials visible on the page), plus `address` limited to locality and country.
- No email. Truthful `dateModified`, derived from content changes, not from build time.
- Validate with the Rich Results Test and the Schema.org validator. See [ProfilePage](https://developers.google.com/search/docs/appearance/structured-data/profile-page).

### 11.3 Crawler policy (`robots.txt`) and Cloudflare overrides

**Recommendation for a personal portfolio whose goal is visibility: allow everything.** Being in search indexes, in AI answer engines, *and* in model training helps assistants know who Hamza is. Training opt-out is an owner decision (§15).

```text
# hedhly.com — portfolio. Public content; crawling welcome.
User-agent: *
Allow: /

# Owner option: stay in AI search but opt out of model training.
# Uncomment the groups below and rebuild.
# User-agent: GPTBot
# User-agent: ClaudeBot
# User-agent: Google-Extended
# User-agent: Applebot-Extended
# User-agent: CCBot
# Disallow: /

Sitemap: https://hedhly.com/sitemap.xml
```

| Class | User agents | Default |
| --- | --- | --- |
| Search indexes | Googlebot, Bingbot, Applebot, DuckDuckBot | Allow |
| AI search / answer engines | OAI-SearchBot, Claude-SearchBot, PerplexityBot | Allow; these drive citations |
| User-triggered fetchers (an agent acting for a person) | ChatGPT-User, Claude-User, Perplexity-User | Allow. They may not consult robots.txt at all |
| Training | GPTBot, ClaudeBot, Google-Extended (a control token), Applebot-Extended, CCBot | Allow by default; owner may opt out |

Cloudflare can silently override this file, as the reference site shows. Check in the dashboard:
1. **AI Crawl Control / "Block AI bots"**: off, or set to a policy that matches the table.
2. **Managed robots.txt / Content Signals**: off, so our file is served as written. If the owner wants content signals, add them to our own file, e.g. `Content-Signal: search=yes, ai-input=yes, ai-train=yes`. This is a non-standard Cloudflare proposal; treat it as advisory.
3. **Bot Fight Mode / WAF**: make sure it doesn't challenge verified crawlers. After launch, check Security → Events for blocked bots.

robots.txt is not access control: it protects neither the email nor previews. Previews get `noindex`, and the email is protected by the reveal.

### 11.4 Discovery files

| File | Status | Notes |
| --- | --- | --- |
| `/robots.txt` | Required | As above; `text/plain` |
| `/sitemap.xml` | Required | 12 URLs with `xhtml:link` hreflang generated from the same route data as the HTML; truthful `lastmod` only |
| `/404.html` | Required | Real 404 status; `noindex`; links to `/de/` and `/en/` |
| `/llms.txt` | Ship (cheap) | Markdown summary: who, what, where, the page list per language, a note that the email is reveal-only. No indexing or ranking promise. Must be `text/plain`, not the homepage HTML as today |
| `/index.txt`, `/en/index.txt` | Keep | Plain-text exports for simple agents; `noindex`; not in the sitemap |
| `/.well-known/security.txt` | Ship | RFC 9116. `Contact: https://hedhly.com/de/explore/profile/` (a URL, so the email isn't exposed), `Expires:` ≤ 1 year (the build fails if it is close), `Preferred-Languages: de, en`, `Canonical:`. Credibility signal for a DevSecOps engineer |
| `/humans.txt` | Optional | Fun geek touch; no email |

### 11.5 Writing content that AI answers can use

- Each document starts with a 2–3 sentence factual summary naming the person, role, location, and core stack. Answer engines tend to quote this kind of self-contained passage.
- Use the same entity string everywhere: "Hamza Hedhly — DevSecOps & Azure Cloud Engineer, Düsseldorf".
- Mark up dates as `<time datetime>` and facts as `<dl>`, `<ul>`, and headings, not as images or CSS-generated text.
- Nothing important lives only behind a click or in `::before` content (the reference's mistake).
- Agents navigate by accessible names. Native links and buttons with clear labels are the agent API; there is no special agent endpoint.

### 11.6 Submission and monitoring

- After release, submit the sitemap in Google Search Console and **Bing Webmaster Tools**. Bing's index feeds several AI assistants.
- Inspect a German and an English URL in each.
- Turn on Cloudflare **Crawler Hints**, which sends IndexNow pings to participating engines on content change, instead of hand-rolling IndexNow calls.
- Review indexing, soft-404 counts (they should drop to zero), queries, and AI referrers (`chatgpt.com`, `perplexity.ai`, `copilot`) about 2 and 6 weeks after launch. No recurring monitor is created here.
